## Plain-English summary

The new Lean program `su2plaq_rishon_cert` takes a certificate: a gate list, a declared target (a $1296\times1296$ matrix written with exact numbers) and a global phase. It runs the gates exactly, symbolically in the three angle variables, on each of the 1296 inner link-configurations (called codes) and demands that the result is exactly the phase times the target column, with all helper qubits back at 0 and nothing outside the 1296 codes. The declared target is not trusted: the checker computes the SHA-256 fingerprint of the target's text and compares it with five constants compiled into the checker (`Pins3.lean`); the 1296 codes are generated by the checker itself. I rebuilt the physical targets separately with dense matrix exponentials, tried about 2 000 deliberately broken certificates, and elaborated the theorem file myself. All behaved correctly.

## 2. Trust base (reading `Check3.lean`, `Gates3.lean`, `Laurent3.lean` against `prompts/203` section 2)

What the checker accepts, from the source: `check c = true` iff `validate` passes and, for every inner code $c_k$ ($k=0..1295$), `runGates3` of the gate list on the single basis state $|c_k\rangle$ (ancillas 0) is structurally equal (sorted by basis integer, Laurent coefficients over $K=\mathbb{Q}(i,\sqrt2,\sqrt3)$ in sorted canonical form) to
$$k\,z^{\mathbf m}\sum_{c'} V_{c'c_k}\,|c'\rangle ,$$
the output of `expected`. Equality of two canonical lists is equality of the sparse vector, so "no weight outside the code space" and "ancillas back at 0" are part of the same identity; a coefficient that is a zero polynomial is dropped, a nonzero one in a key outside the column is a mismatch.

### 4a. The rescaled base is sound (builder's remark)

Take a certificate at base $(d_\alpha,d_\beta,d_\gamma)$ and a positive integer vector $\mathbf r$. Substituting $z_x\to z_x'^{\,r_x}$ (so $z'_x=e^{i\theta_x/(d_xr_x)}$) maps Laurent polynomials injectively to Laurent polynomials, multiplies every exponent by $r_x$, and preserves all products and sums, so the gate replay, the phase and the target identity carry over exactly. This is the same unitary written with a finer unit angle. The checker accepts exactly this: it requires cert base $=\mathbf r\cdot$ target base and divides the target exponents by $\mathbf r$ before the SHA comparison. It does not accept a half-way rescale: base doubled with gates, target and phase unscaled is rejected whenever the slot is used (`base x2 alpha only` on $U_E$, step, $U_D$, `r06-F3-006`; all rejected), as is "gate exponents $\times2$, base unchanged" on every base that uses the $\alpha$ slot. Not a hole.
